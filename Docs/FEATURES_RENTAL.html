1. Обзор

Система добавляет к прокату мотоциклов четыре связанных блока:

  • Доставка — клиент выбирает адрес и окно; система сама считает тариф и назначает ближайшего свободного курьера.
  • Курьеры — отдельная регистрация с одобрением админом, смена, геолокация из браузера, один активный заказ.
  • Чеки — после оплаты создаётся эмулированный фискальный чек с позициями, ФН/ФД/ФП и QR.
  • Фото — клиент фиксирует состояние мотоцикла при получении и возврате; минимум 4 фото на этап.

Жизненный цикл одной аренды:

Создана → Оплачена → Выдана → Завершена
                    ↘ Отменена

Одновременно с бронью:
  Dropoff (доставка)  — назначается курьеру ближе к окну
  Pickup  (забор)     — создаётся сразу, назначается ближе к EndDate

ФайлКодКак работает

Host/DeliveryRoutesExtensions.cs/deliveries/*Список по роли, смена статуса, ручное назначение админом, тариф fee-preview.

Логика выбора курьера:

candidates = couriers
  .Where(c => c.IsApproved
      && c.Status == Available
      && c.LastLocationAt >= now - 5 min
      && c has no active delivery)

best = candidates.MinBy(c => Haversine(delivery, c))

delivery.CourierId = best.Id
delivery.Status     = Assigned
best.Status         = Busy

База дополнительно защищена частичным уникальным индексом: у курьера не может быть двух активных доставок.

Формат QR-строки:

t={yyyyMMddTHHmm}&s={amount:0.00}&fn={16 цифр}&i={10 цифр}&fp={10 цифр}&n=1
Сейчас это эмуляция: реальные деньги не списываются, фискальные номера случайные. Для боевого режима реализуется IFiscalService под конкретную кассу (АТОЛ, Orange Data, ЮKassa и т.п.) без изменений в UI.

11. Ручная проверка

  1. Оплатить бронь — статус Paid, появился чек.
  2. Открыть «Мои аренды» → «Получил мотоцикл».
  3. Загрузить 4 фото → «Подтвердить получение» — статус HandedOver.
  4. «Вернул мотоцикл» → 4 фото → Completed.
  5. Открыть чек: позиции, ФН/ФД/ФП, QR, печать.
  6. Админ → «Аренды»: фото «до/после», чек, повтор фискализации.
  7. Курьер → «Мои доставки»: Назначен → В пути → На месте → Доставлено.

Для сценария с доставкой: пока курьер не завершил Dropoff, кнопка «Получил мотоцикл» у клиента заблокирована с текстом «Ждём доставку».

12. Ограничения

  • Фискализация эмулируется; реальная касса подключается через IReceiptService.
  • Фото загружает только клиент; курьер и админ — только просмотр.
  • Интерфейс курьера пока не показывает фото клиента, хотя API это разрешает.
  • Курьер может завершить забор независимо от подтверждения возврата клиентом.
  • Нет push-уведомлений о назначении и прибытии курьера.
